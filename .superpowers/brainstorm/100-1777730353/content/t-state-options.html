T-State Timing: Instruction-Level vs. Cycle-Level

Enabling contended memory support for ZX Spectrum accuracy

Current: Atomic Timing

INC (HL) - 11 Cycles
  1. Read HL value from memory (0 cycles)
  2. Increment value (0 cycles)
  3. Write back to memory (0 cycles)
  4. Wait 11 Cycles at end.
Issue: If ULA stops the CPU in step 1, we can't emulate it correctly.

Proposed: T-State Precision

INC (HL) - 11 Cycles
  1. Wait 4 Cycles (Fetch Opcode)
  2. Wait 3 Cycles (Read HL)
  3. Wait 1 Cycle (ALU Delay)
  4. Wait 3 Cycles (Write HL)
Benefit: The ULA can pause the CPU at any specific clock cycle.

Implementation Approaches

A

Bus-Driven Delay

Modify IBus to handle timing. _bus.Read(addr) automatically increments TotalCycles. Simple but less flexible for complex internal CPU delays.

B

Explicit T-State Ticks

CPU manually calls Tick(n) between operations. Maximum control over internal Z80 sub-cycle timing (M-cycles).

C

Generator-Managed (Recommended)

The Code Generator injects the correct T-State delays between memory operations based on Z80 timing tables. Cleanest CPU logic, automated expansion.
