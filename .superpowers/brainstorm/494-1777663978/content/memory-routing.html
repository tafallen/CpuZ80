Memory Routing: O(N) → O(1)

Refactoring AddressDecoder for professional-grade performance

Current Bottleneck: O(N) Lookup
// Every read/write iterates the list
foreach (var mapping in _mappings) {
    if (address in mapping) return mapping.device;
}
Problem: Scalability. As more devices are added, emulation slows down.
Proposed Solution: 256-Page Table (O(1))
// O(1) Array Lookup
return _pages[address >> 8].Read(address);
Benefit: Constant time routing regardless of mapping complexity.

Select Implementation Approach

1

Simple Pointer Array

Array of 256 IBus references. Fastest, but requires devices to know their own base offset.

2

Page Entry Struct (Recommended)

Array of 256 structs containing { Device, BaseAddress }. Preserves existing 'clean' device logic.

3

Dual R/W Tables

Separate tables for Read vs Write. Ideal for write-protected memory or bank switching.
